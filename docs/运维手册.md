# 电商 ERP 运维手册（首版）

适用于仓库内的 Docker 部署栈和本地开发环境。生产域名、证书与服务器尚未配置，当前仅完成本地部署冒烟；不能据此宣称已经生产发布。

## 组成与配置

部署栈由 nginx 前端、FastAPI 后端和 Redis 组成，MySQL 在容器外。部署配置为 `deploy/compose.yml`，生产 HTTPS 叠加配置为 `deploy/prod/compose.yml`。开发用根目录 `docker-compose.yml` 与部署栈独立，不要误启动其中的 MySQL。当前本机开发数据库为 `127.0.0.1:3306/erp`（MySQL 5.7）；实际生产数据库版本需单独验证兼容性。

私密配置放在忽略提交的 `deploy/.env`，尤其是 `DATABASE_URL`、至少 32 字符的随机 `JWT_SECRET` 和 `PUBLIC_ORIGIN`。不要把连接串、私钥、数据库备份或验证码写入仓库、工单和日志。容器内连接宿主 MySQL 时使用 `host.docker.internal`；迁移前逐字核对目标库名。更换 JWT 密钥会让已有令牌失效，应按计划维护。

AI 助手密钥只配置在后端运行环境：本地支持 `DEEPSEEK_APIKEY`、`DEEPSEEK_API_KEY` 或 `ASSISTANT_API_KEY`；部署时放入受保护的 `deploy/.env`，不要配置到 `VITE_*` 前端变量。模型可用 `DEEPSEEK_MODEL` 或 `ASSISTANT_MODEL` 覆盖，未设置时使用规范 ID `deepseek-flash`；Provider host 固定为 `https://api.deepseek.com`。正式启用前应确认公司助手配置、Redis 限流/并发额度以及管理员录入的月预算和 token 单价。默认每用户每分钟最多 10 次、并发 1；预算未设置时不代表供应商费用为零或已有费用上限。日志和审计不得包含 API Key、聊天正文或未脱敏业务数据。通过 `/assistant/admin/config` 配置密钥时，密钥会使用 `ASSISTANT_CONFIG_ENCRYPTION_KEY` 加密存库；设置该项后不得丢失对应密钥。

采购计划快捷录入只对具有 `purchase:create` 的账号开放；当前不开放其他单据、已保存单据修改、审批提交或履约操作。部署前须应用 Alembic head（含迁移 `0023` 的采购计划创建幂等表），并确认前后端版本一致。保存使用 `Idempotency-Key`；遇到客户端超时应先查询创建请求状态，不要换请求标识或改载荷重试。审计只保留操作者、来源和请求关联信息，不应写入完整提示词或敏感原文。

## 发布与验证

在已有授权、备份和维护窗口的前提下，从项目根目录执行：

```powershell
./deploy/prod/backup.ps1
./deploy/deploy.ps1
./deploy/prod/check.ps1
```

`deploy.ps1` 会构建镜像、执行 Alembic 数据库迁移并更新容器；**不是只读命令**。其具体参数和准备步骤见 `deploy/README.md`。生产 HTTPS 配置、证书挂载与发布前检查见 `deploy/prod/README.md`；生产叠加配置不由上述基础一键脚本自动启用。发布后检查 `/healthz`、`/api/health`、登录、订单及库存关键路径，并查看 `docker compose --env-file deploy/.env -f deploy/compose.yml ps` 与 `logs --since 1h`。若前后端版本不一致，应先核对镜像构建时间和迁移版本，不要直接重放迁移。

2026-10-10 经用户授权，本地 `erp` 已升级至 `0025`（包括通知 Outbox/Inbox/投递尝试及提醒扫描检查点）。后续部署时以仓库 `backend/alembic/versions/` 最新 head 为准；在 `backend` 目录可用 `.\.venv\Scripts\alembic.exe current` 和 `heads` 核对。MySQL DDL 不是事务性操作，迁移失败后必须先检查实际 schema 和 Alembic 版本，再制定修复方案，**不要盲目重复执行或自动降级**。

## 备份与恢复

`deploy/prod/backup.ps1` 使用 `mysqldump --single-transaction` 生成 SQL 文件和 SHA256，默认写入被 Git 忽略的 `deploy/backups/`。备份只验证了导出和非空，不能代替恢复演练。应配置定时执行、加密的异机副本、访问控制、保留期限及失败告警，并定期核对 SHA256。

恢复演练只能在**独立测试库**进行：先确认目标库与现有业务库不同，创建空库并导入备份，然后核对 Alembic 版本、核心表行数与典型业务页面。未经负责人审批不得覆盖 `erp` 或生产库。实际回滚需要同时考虑数据库结构、业务数据和应用镜像，不能只回滚容器版本。

## 监控、日志与故障处理

`deploy/prod/check.ps1` 检查前后端健康端点及容器状态，可由任务计划程序定时调用并对非零退出告警。Docker 容器健康检查和自动重启已配置；日志使用 JSON 文件轮转（每文件 10 MB，最多 5 个）。生产仍需外部监控、集中日志、磁盘/数据库/Redis 告警和证书到期告警，目前仓库不提供托管告警平台。

- `/healthz` 失败：检查 nginx 容器、端口绑定和代理配置。
- `/api/health` 失败：检查后端容器、启动日志、数据库/Redis 连通性与迁移状态。
- 登录 401/403：检查令牌有效期、角色/数据范围、公司 IP 策略；不得通过放宽权限绕过。
- 数据不同步：首先确认对应外部接入是否仍为 mock；mock 成功不等于外部平台、物流或金蝶成功。
- 备份失败或磁盘不足：先保护已有备份与日志，再排查权限、空间和 MySQL 连接；不要删除唯一可恢复副本。

## 测试与变更记录

### 站内通知运维

部署审批/采购到货通知前应用 `0024`，启用配置型提醒前还需 `0025`。API、worker 和 beat 必须使用相同数据库、Redis、JWT 及提醒配置。已有生产 Celery 入口为 `app.integrations.platform_tasks:celery_app`；运维明确授权后启动一个 beat 和至少一个 worker，不将本卡的 `scripts.task094_runtime` 当成生产入口。TASK094 在 Windows 使用 `--pool solo` 验证真实任务消费，正式环境的并发与进程模型需另行容量验证。

Outbox 每 10 秒扫描，实时尝试每 10 秒补偿，提醒每 60 秒扫描。提醒默认 `NOTIFICATION_REMINDER_RULES=[]`，启用条件见[定时提醒配置与验收](定时提醒配置与验收.md)。不要使用测试 SLA 替代业务确认的阈值。审批超时以应用写入的待办事件 UTC 时间计时，不能用受 MySQL 会话时区影响的默认创建时间推断截止时间。

重点监控按公司统计的 Outbox `PENDING/RETRY/PROCESSING` 数量、最早到期时间及租约超期、`FAILED` 和 `last_error_code`；提醒扫描表的 `status/failure_code/last_run_at`；实时尝试的失败/重试。`NO_CONNECTION` 仅表示当时无订阅者，不意味着站内 Inbox 丢失。Redis 中断不应回滚已提交业务事实，恢复后依靠 Outbox 和 Inbox 扫描补偿。

失败重投目前是后端受控服务 `notification_service.requeue_failed_outbox`，未提供公开 HTTP 入口或管理界面。只允许有 `notification:manage` 的同公司身份、`FAILED` 事件，在审计下沿用原事件键重投；仍复核业务状态和接收权限。不得直接改数据库状态、放宽权限或从 payload 重做业务。尚未提供积压告警平台、自动归档/清理作业和保留期限管理；未确认期限前不删除历史记录。

SSE 代理必须关闭缓冲/缓存、允许 `Authorization` 和 `Last-Event-ID`、保留长连接超时。仓库 nginx 配置已有专用 `/api/notifications/events` 段；TASK094 只验证本地直连 API/Vite，未运行真实 nginx/HTTPS 代理，不能据此宣称生产代理、容量或发布可用。

前端在 `frontend` 目录运行 `npm run typecheck`、`npm test`、`npm run build`；后端在 `backend` 目录运行 `.\.venv\Scripts\python.exe -m pytest -q`。依赖 Redis 的测试需先提供正确的测试 Redis 连接。GitHub Actions 工作流已配置，但仓库尚未记录远程 CI 成功与正式发布证据。每次发布记录版本、迁移、备份路径、健康检查和已知问题。

角色助手浏览器回归使用 `frontend/e2e/assistant-roles.spec.ts`，可通过 `E2E_BASE_URL` 和 `E2E_API_BASE_URL` 指定测试地址；账号从本地 `docs/角色账号/` 读取。该回归会产生助手用量/审计记录并调用真实模型，但不创建业务单据。禁止把 `core-flow.spec.ts` 当作助手 E2E，它会创建采购计划、订单和发货数据；快捷录入保存验收必须使用经确认的独立测试库，不能指向 `erp`。
