# 遗留项与二期清单

本清单区分“已提供接口/mock”和“已真实接入”。任务卡标记 DONE 只表示在当时确认的范围内完成，不代表真实第三方上线。

## 发布前必须完成

1. **真实生产发布**：目前没有生产域名、服务器和证书，HTTPS 配置只完成静态校验，未进行真实发布。需确定域名、证书来源、部署账号、环境隔离、生产 MySQL 和发布窗口；完成真实证书检查与端到端演练。
2. **备份恢复与告警**：已有 SQL 导出脚本、容器健康检查和日志轮转；尚未在独立测试库完成恢复演练，也没有异机备份、集中日志或外部告警平台。正式上线前需落实负责人和周期。
3. **远程 CI 与发布证据**：测试/构建工作流已配置，尚未取得 GitHub Actions 真实运行结果；无自动发布流水线。需记录一次完整 CI、镜像与迁移版本、部署冒烟结果。
4. **性能容量验收**：证明查询次数与索引使用改善，但本地业务库仅 6 条订单。需用脱敏、代表性数据制定并验证 P95、批量打印/PDF 最大订单数和并发指标。

## 二期：外部系统真实接入

- **平台订单**：仅统一适配接口、mock 抓单/回传和任务入口；待确定目标平台、API 协议、凭据、回调验签、幂等与异常重试。
- **物流取号/面单**：仅适配接口和 mock 号码；待承运商资质、真实协议、取号/回收/打印联调。`MOCK-` 运单号不得用于真实发货。
- **短信及第三方仓储**：仅接口与 mock。正式短信需服务商、模板、密钥、发送成本/频控与回执；第三方仓储需厂商协议、库存一致性及失败补偿。本地验证码仅在明确的调试条件下可见，生产必须关闭。
- **金蝶**：按用户要求仅保留金蝶适配接口与本地 mock，不接入其他财务系统。真实金蝶同步需版本/协议、凭据、科目映射、凭证回执、余额对账和审计验收。

## 后续质量维护

- 扩大浏览器 E2E 对各角色、异常流、审批及财务链路的覆盖；现有真实 MySQL E2E 只覆盖已选关键链路。
- 给二期接入补齐契约测试、限流、超时、重试、监控与降级演练；对已有 TODO/旧任务卡描述按实际实现同步更新。
- 文档与 API 变更同步：每次修改路由后运行 `backend/scripts/export_openapi.py` 重新导出 `docs/openapi.json`，并更新用户/运维说明。
